# Construct v1.1.0

Models come alive. Construct 1.1 makes the NetLogo bridge something a student can use in a minute
and a teacher can trust: one command in NetLogo turns a run into a construct, nearly every model in
NetLogo's library records unattended, every construct of a run explains how to read it and replays
the run tick by tick, a model can move to music, and a run can leave as a film or a 3D model for
Blender, or run by itself on a museum screen.

## What's new

**Runs to music.** `construct:music "track.mp3"` makes each tick a moment of a track (30 a second by
default), and a model's own code can listen at every tick: `construct:kick` (a pulse on each kick
or bass hit), `construct:energy`, `construct:high` and `construct:hit`. `construct:run` then runs
for the length of the track. The construct of the run plays back in time with it: its replay bar
plays the track, the build follows the run's clock, and the light and accents follow the music;
the track's fingerprint is under the data lock. In the stock Fireflies model, given the beat as
one more flash to see, the fireflies' flashing locks to the kicks: 110 of 119 synchronised flashes
fell within two ticks of a kick in our test run.

**Runs as films.** A construct holds a run's shape; a film holds its motion. In Blender (the
add-on's File > Import > NetLogo Run, `construct netlogo-film run.jsonl --out film.mp4`, or
`(construct:draw "auto" "film" true)` in NetLogo), the recording itself is drawn: every agent at
every tick as moving light with a trail, in its own NetLogo colours, the world's edge as a line of
light, with the run's track at the run's clock. Nothing is sampled, so a three-minute flock of 200
birds stays 200 birds for three minutes. NetLogo 3D runs are recorded with their heights and fly in
their box; hidden turtles are recorded and stay unlit.

**Kiosk pages.** `construct build --kiosk` makes a page for a museum screen or a classroom wall: it
fills the screen with a label, loops by itself once the construct has settled, opens to a touch,
plays a run's music after the first touch and keeps the screen awake.

**Construct for NetLogo**, a NetLogo 7 extension ([hosts/netlogo](../../hosts/netlogo/README.md)).
Add `extensions [construct]` to a model and type `construct:run` in the Command Center: it runs the
model as its buttons do, records what is worth recording, lets the run go until the model stops by
itself, chooses the view the data suits and opens the construct in the browser. A model that never
stops is drawn after 1000 runs of go, and says so; `construct:run-for 3000` runs longer. The
step-by-step commands (`construct:start`, `construct:track-…`, `construct:record`,
`construct:draw`) are there for full control, and `(construct:draw … "model" true)` also writes a
3D model of the run. Install: unzip `construct-1.1.0.zip` into a folder called `construct` in
NetLogo's `extensions` folder (a listing in NetLogo's Extensions Manager is planned). Recording
needs only NetLogo; drawing needs Python 3.10 or newer.

**The Models Library, unattended.** Of NetLogo 7.0.4's 445 two-dimensional models, 388 now record a
run (at least two records) with no hand edits, from 256 at 1.0. Setup and go come from the model's
own buttons, turtle buttons and step buttons are understood, a model that never starts the tick
counter is recorded by steps, and a clock that moves in fractions (GasLab, system dynamics)
records every step. Most of the rest wait for a player or a classroom.

**Reading a run.** Every construct of a run carries its legend, shown from the start and kept
inside the window, a **How to read it** panel, and a replay bar: drag it, or press play, and the
construct is drawn up to that tick, with the tick and the run's counts beside it. `--view auto`
chooses the view: a network where something spread or that grew, patches that changed, two counts
that cycle, or the agents' paths.

**Critic rounds for a run (opt-in).** Construct's improvement rounds now judge a construct of a run
by its own standard: every label and milestone against the recording's facts and counts, and how a
student would read it. With GPT-6.1 Sol as the blind critic, three rounds on Virus on a Network
raised accuracy from 1 to 3 (of 3), and a planted false milestone was its first, critical defect.

**A run as a 3D model (opt-in).** `construct netlogo … --solid --glb run.glb` adds solids drawn from
the recording (each turtle a sphere where it rose, a cycle as a tube, a spread as a surface) and
exports the run in its own NetLogo colours, its build replaying the run.

**NetLogo for every agent.** The MCP server gains `construct_netlogo_instrument` and
`construct_netlogo_draw`, so Hermes or any MCP client can instrument a model, draw a run, add an
art layer, solids and colours, then compile or export it with the existing tools.

## Fixes

- The ReVox A77's meter faces sat in the plane of their housings and flickered in any solid render;
  the FJ62's glasshouse shared its bottom with the body's top. Both are fixed in the examples.
- The field view's fronts are declared floating, so a run whose first front sits above the floor
  passes the audit.
- The recorder's own names no longer clash with a model's.

## Compatibility

The scene and geometry contract keeps its id, `construct/0.2`, and changes nothing that exists:
1.1 adds two optional scene keys, `presentation.labels` and `reading` (with an optional `music`, for a
run recorded to a track), one optional shape type, `rings` (a closed surface through closed rings), and
the optional `reading` in geometry. A page whose scene uses neither,
and that is not built with `--kiosk`, is byte for byte the 1.0 page. NetLogo recordings gain
optional header keys (`music`, `zcor`, the world's `min-pzcor` and `max-pzcor`) and, for NetLogo 3D,
each turtle's height last in its row; a 1.0 recording reads as before. The three NetLogo
examples are regenerated with readings, so their data locks changed; their data did not.
