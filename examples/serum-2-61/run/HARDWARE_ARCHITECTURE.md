# Native Serum 2: proposed hardware architecture

Status: engineering concept, not a working DSP implementation. D = documented Xfer behavior; R = published reference precedent; I = proposed design/estimate; U = user premise. Physical model dimensions are packaging allowances, not a PCB layout or safety certification.

## Compute contract before processor selection

**U:** Xfer's synthesis architecture can run as native firmware/application code on dedicated hardware. This is a purpose-built boot-to-instrument appliance with native parameter model, graph editors, file management, scheduler and audio engine. It does not launch a desktop DAW or host the existing plugin. A general-purpose instruction-set CPU inside an instrument does not imply a plugin-host product.

**D:** Xfer publishes no usable embedded benchmark, core count or RAM requirement. [CPU guidance](https://support.xferrecords.com/article/51-serum2-sound-design-guidelines-for-optimizing-cpu-usage) identifies unison cost; the manual p.216 includes grains/unisons in its displayed voice count. Consequently, neither a named CPU nor a guaranteed worst-case note count is claimed.

**R:** [Korg NAUTILUS specifications](https://www.korg.com/us/products/synthesizers/nautilus/specifications.php) describe a multicore allocation separating effects from voice processing and dynamic allocation between synthesis engines. This establishes appliance precedent, not Serum performance equivalence. [Waldorf Quantum MK2](https://waldorfmusic.com/quantum-mk2/) establishes 61-key poly-pressure and substantial sample storage as real instrument features.

**I:** provision a replaceable compute carrier, 170 x 135 mm, with a 100 x 80 mm module envelope and a 35 W sustained / 55 W short-term compute allowance. Candidate class: industrial 64-bit SIMD-capable multicore CPU/SoC with strong single-thread performance, real-time OS support, native compiler support, display output, PCIe/NVMe and a deterministic audio interface. The model shows a generic processor package and memory packages; it does not assign a vendor or fictional silicon specifications. The instruction set and final module are selected only after native-engine profiling. An NPU or GPU is not assumed to accelerate Serum audio.

Reserve 32 GB RAM and 1 TB replaceable NVMe storage (I). These are product provisions, not documented minimums. Allocate separate read-only factory content, user content, preset database/cache, render scratch and dual firmware partitions. Keep parameter/audio allocation free of filesystem stalls; preload and pin active assets, prefetch streamed samples, and perform database/import/render work outside realtime threads. Display processes never block the audio callback. Firmware applies graph changes atomically at valid audio boundaries.

Acceptance targets (I, to benchmark): 48 kHz base audio rate, 64-sample callback deadline (1.333 ms), 32-note useful flagship test workload at High quality, and under 5 ms key-to-analog onset. The deadline target must include converters, scheduling and key scanning before latency can be claimed. Test 1x/2x/4x, all five engines across A/B/C, 16-unison settings, maximal allowed grains, long releases, full matrix and nested/convolution FX. Retain every legal engine setting; report sustainable per-patch polyphony. Do not silently lower quality, disable an oscillator or remove effects. Benchmark failures require faster compute, revised thermal provisions, or an openly specified voice limit. Offline Ultra rendering remains available for patches beyond realtime capacity.

## Audio path and ports

Native floating-point voice engines -> two digital synthesis filters and native mixer -> Main/Bus1/Bus2 nested FX graph plus Direct -> output-tap/router -> multichannel digital audio bridge -> DAC -> reconstruction/buffer/level/mute -> balanced outputs. Hardware audio remains digital synthesis; the analog section conditions final I/O rather than substituting analog synthesis filters.

R: [TI PCM1690](https://www.ti.com/product/PCM1690) demonstrates an eight-channel 24-bit DAC with TDM/I2S and differential outputs. [TI PCM1862](https://www.ti.com/product/PCM1862) demonstrates a two-channel ADC class. These are examples supporting board/channel plausibility, not locked production parts or system-level noise promises. Eight DAC channels provide six balanced line channels (Main L/R, Aux1 L/R, Aux2 L/R) and a separate stereo headphone feed. Two ADC channels accept stereo line input. Each line output needs a real differential line driver/filter and protection; a jack is not a converter.

I: dedicated audio/interface controller bridges CPU DMA/PCIe to fixed-rate TDM, local low-jitter clock, stereo ADC, eight DAC channels, hardware output mute/watchdog and USB audio. This controller requires actual interface/electrical design. No claim that an arbitrary compute module exposes audio TDM. 24-bit/48 kHz is the initial product mode; DAC capability at 192 kHz does not imply a 192 kHz Serum appliance mode.

Main L/R carries the final patch. Aux pairs can be assigned to documented Main/Direct/bus taps in a separate hardware-output page; using a tap must not alter the native graph. Default Aux muted. Headphones have their own amplifier, analog level knob and source assignment, defaulting to Main. Stereo input is an added asset-capture/monitor facility (I), not a claim that the manual specifies live external input to every Serum engine. Record audio into a file, then load/convert with native sample functions.

Rear (all I): six 6.35 mm TRS balanced line outputs, two 6.35 mm line inputs; DIN MIDI In/Out/Thru; USB-C device (USB audio/MIDI/content transfer), two USB-A hosts (storage, optional HID keyboard or MPE device); sustain plus two expression/pedal inputs; IEC inlet with fuse and hard power rocker. Front-left 6.35 mm headphones. USB roles are printed. Storage is internal NVMe and removable USB; no ornamental unconnected ports. Pedal circuits have ADCs, protection, polarity/type calibration and local status. MIDI In isolated; Thru is buffered hardware; Out separately driven. USB host ports have individual current limiting/ESD. USB device uses a physically separate controller path from host ports. No mandatory network, account or cloud service for playing.

## Keys, controls and display electronics

I: 61-key C2-C7 action, 36 white and 25 black keys, 23.5 mm white-key pitch, approximately 846 mm playing span, 170 mm visible key length. Velocity, release velocity and per-key pressure have calibration curves. Exact supplier/action envelope must be obtained before tooling. [Magnolia](https://frap.tools/magnolia/) and Quantum MK2 document production 61-key poly-pressure actions, supporting feasibility without claiming a specific one is licensed here.

Independent key scanner/control MCU timestamps key events and pressure, scans pedals and local buttons, and forwards a bounded event queue. Proposed targets: 1 kHz key/pedal scan and pressure updates at 250 Hz; jitter and end-to-end onset require measurement. Distributed panel boards scan encoders/buttons/faders and drive state LEDs/displays; differential serial buses connect them to the UI controller. Audio-rate oscillator/filter modulation never passes through these slow control buses. Five envelope faders are scanned ADC controls with pickup; absolute state is shown before engagement. Encoders retain parameter IDs across modes.

Central 7-inch-class 155 x 87 mm active glass, approximately 1280 x 720 IPS with optional capacitive touch; panel mechanical rotation is 8 degrees towards the player. Six contextual push encoders and six soft keys below it. Three oscillator strips and two filter strips use small high-contrast local LCD/OLED context windows. Macro names use a narrow shared display. Modulation assignment has an independent status window, signed AMOUNT encoder and explicit ASSIGN/INSPECT/POLAR/CURVE buttons. Display resolution/brightness/component life are procurement specifications (I), not measured installed-panel behavior. Burn-in risk, readability and spare-part support need supplier validation.

## Power and thermal design

I: internal shielded universal-input **150 W class** supply, allocated 130 x 75 x 38 mm at rear-left, with protected IEC input, protective-earth bonding, a mains segregation barrier and insulated cover. Service access is for technicians with power disconnected. Local conversion provides compute rail, regulated 5/3.3 V control/audio rails and quiet bipolar analog rails as required by selected line/headphone stages. A power supervisor mutes outputs before startup/shutdown, flushes user data, controls soft-power hold and handles brownout recovery. No mains circuitry under a performance wheel.

Budget (design estimate): compute 35 W sustained/55 peak; RAM/storage/bridges 14 W; displays/UI 10 W; controls/keybed 6 W; audio/analog 8 W; fans 3 W; USB external allowance 10 W; conversion loss 10 W. Approximately 96 W sustained allowance / 116 W short peak; this is a deliberately conservative provision, not a measured typical draw. The 150 W supply gives margin. USB power budget is explicitly bounded.

Compute thermal assembly: 160 x 85 x 22 mm fin stack with heatpipe/contact plate, plus twin 60 mm slow fan modules and rear exhaust chamber. Protected underside intake sits at the rear electronics bay with 12 mm feet; airflow avoids the exposed key slots. Main analog board is at rear-right, away from supply/fans. Internal duct and metal divider keep exhaust from recirculating into input converters. Planned duct cross-section ~120 x 45 mm; planned grille open area >3500 mm². At 75 W exhausted heat and 15 C air rise, ideal flow is ~8.8 CFM (P/(1.2 kg/m³ x 1005 J/kg/K x 15 K)); specify >=12 CFM at actual duct resistance after acoustic testing. The model represents fan volumes and fin bank, not a validated fan curve or thermal simulation. Quiet mode can limit voice allocation visibly; it cannot silently alter sound quality. Test sealed-under-stand, blocked-intake warning, hot stage, fan failure and case-touch temperatures. Verify keybed temperature and acoustic noise with real prototypes.

## Physical zoning and service

Designed case envelope **1080 W x 520 D x approximately 160 H mm including controls and feet**. Lower tray is a real open tub with 2.5 mm folded/machined aluminum walls, not a solid block. End structures are separate faceted aluminum castings/machined parts; removable keybed bolts to two rails. Controls mount to a separate 3 mm removable deck with a rear service hinge and retention stay. Hinge is for technician service, not a required playing adjustment. Harness service loops and disconnects permit the whole panel to lift without stressing displays.

Rear electronics bay clear plan allowance ~1000 x 235 mm, local usable height 60-100 mm below the sloped deck. Compute center-left, segregated supply far left, converters/analog far right, rear I/O boards behind their own connectors; UI boards above with a defined clearance. Keybed occupies the front ~190 mm of depth; no compute board overlaps moving key travel. Power/data/audio harnesses route separately. NVMe and fan modules are reached through a removable underside hatch; shielded supply and panel require technician disassembly. Four feet, stand-contact rails, structural crossmembers, standoffs and captive fasteners are represented. Quantitative collision/clearance checks are saved separately from Construct's visual audit.

Before manufacture: authenticated release reconciliation, native DSP port and reference-audio comparisons, processor benchmark, PCB/schematic design, signal-integrity/EMC/ESD, converter noise/latency and USB conformance, thermal/acoustic testing, mains compliance, keybed procurement, tolerance stack, hinge/harness fatigue, drop/vibration and ergonomic prototype testing. These are unresolved engineering tasks, not claims fulfilled by a 3D model.
